# Code for the hypertension-subtype genetic analyses

This code release contains four R scripts corresponding to four study-specific analyses reported in the manuscript:

1. construction of baseline blood-pressure phenotypes;
2. comparison of associated loci across hypertension subtypes;
3. pairwise comparison of GWAS effects while accounting for shared controls;
4. effective-sample-size standardization.

The scripts are self-contained and receive all input and output paths as command-line arguments; no machine-specific paths are embedded in the code. The participant-level UK Biobank source data and derived participant-level outputs are not included. Analysis 1 must be run within an approved UK Biobank analysis environment using a de-identified input table.

The primary GWASs were performed with REGENIE following the UK Biobank Research Analysis Platform end-to-end GWAS workflow: <https://dnanexus.gitbook.io/uk-biobank-rap/science-corner/end-to-end-target-discovery-with-gwas-and-phewas>. Study-specific phenotype definitions and covariates are reported in the manuscript. The released scripts focus on the study-specific phenotype and post-GWAS procedures rather than duplicating the platform tutorial.

## Software and general conventions

- R >= 4.3
- `data.table` >= 1.15
- PLINK 1.9 for the LD calculations used by analysis 2

All tabular inputs are tab-delimited text files. Missing values may be encoded as `NA`, an empty field, or `.`. All genomic positions are on GRCh37. LD was calculated using the 1000 Genomes Project Phase 3 European reference panel.

The examples below assume that the four R scripts are located in the current working directory. If they are stored in an `R/` directory, prefix each script name with `R/`.

## Recommended execution order

Analysis 1 constructs the phenotype and is performed within the approved individual-level data environment. Analyses 2–4 are post-GWAS analyses. Analysis 3 can use the locus-edge output generated by analysis 2, and analysis 4 directly uses two outputs generated by analysis 3:

```text
02_compare_subtype_loci.R
          |
          v
03_compare_effects_shared_controls.R
          |
          v
04_standardize_effective_sample_size.R
```

## 1. Baseline phenotype definition

Script: `01_define_hypertension_subtypes.R`

The input is a de-identified table with the following canonical columns:

| Column | Meaning |
|---|---|
| `participant_id` | De-identified local analysis identifier |
| `auto_sbp_1`, `auto_sbp_2` | Automated SBP readings at baseline |
| `auto_dbp_1`, `auto_dbp_2` | Automated DBP readings at baseline |
| `manual_sbp_1`, `manual_sbp_2` | Manual SBP readings at baseline |
| `manual_dbp_1`, `manual_dbp_2` | Manual DBP readings at baseline |
| `preanalysis_eligible` | Passed the non-BP exclusions described in the manuscript |
| `antihypertensive_medication` | Receiving antihypertensive treatment at baseline |
| `hypertension_history` | Prior hypertension history used to exclude reference participants |
| `age` | Baseline age in years |

In the internal UK Biobank extraction, automated DBP and SBP corresponded to fields 4079 and 4080, and manual DBP and SBP corresponded to fields 94 and 93, respectively; array indices 0 and 1 at baseline instance 0 were used. Generic column names prevent the public script from depending on a particular UK Biobank export format.

SBP values below 70 or at least 270 mmHg and DBP values below 50 or at least 150 mmHg are treated as outliers. Available baseline readings are averaged. The mutually exclusive case definitions are IDH (DBP >=90 and SBP <140 mmHg), ISH (SBP >=140 and DBP <90 mmHg), and SDH (SBP >=140 and DBP >=90 mmHg). The strict reference group has SBP <120 and DBP <70 mmHg and no prior hypertension history. Participants receiving antihypertensive treatment are not assigned to a case or reference group.

Run:

```bash
Rscript 01_define_hypertension_subtypes.R input.tsv output/phenotypes
```

The script writes the full baseline classification and five case-control phenotype tables. Participant-level inputs and outputs must not be uploaded to a public repository.

## 2. Cross-subtype locus comparison

Script: `02_compare_subtype_loci.R`

This analysis requires three inputs.

### 2.1 Combined FUMA locus table

Required columns are:

```text
phe  locus_id  chr  locus_start  locus_end  lead_snps
```

The `phe` column contains `IDH`, `ISH`, `SDH`, `IDHL`, or `ISHH`. Multiple lead SNPs within one locus are separated by semicolons and are all retained.

### 2.2 Genome-wide significant SNPs within the FUMA loci

Required columns are:

```text
study_snp  phe  locus_id  study_chr  study_pos  study_p
present_in_EUR2m  panel_chr  panel_pos
```

All rows must satisfy `study_p < 5e-8`. `present_in_EUR2m`, `panel_chr`, and `panel_pos` record evaluability and coordinates in the European LD reference panel.

### 2.3 LD manifest

The LD manifest contains one row for each phenotype and two columns:

```text
phenotype	path
IDH	/path/to/idh_all_GWS_SNPs_250kb_LD.ld
ISH	/path/to/ish_all_GWS_SNPs_250kb_LD.ld
SDH	/path/to/sdh_all_GWS_SNPs_250kb_LD.ld
IDHL	/path/to/idhl_all_GWS_SNPs_250kb_LD.ld
ISHH	/path/to/ishh_all_GWS_SNPs_250kb_LD.ld
```

Relative paths are interpreted relative to the manifest file. PLINK LD output must contain `CHR_A`, `BP_A`, `SNP_A`, `CHR_B`, `BP_B`, `SNP_B`, and `R2`.

For each phenotype, LD can be generated from the full list of genome-wide significant regional SNPs using:

```bash
plink --bfile EUR2m \
  --r2 \
  --ld-snp-list phenotype_GWS_SNPs.txt \
  --ld-window-kb 250 \
  --ld-window 999999 \
  --ld-window-r2 0 \
  --out phenotype_all_GWS_SNPs_250kb_LD
```

The R script reapplies the prespecified overlap criteria: `r2 > 0.2` within +/-250 kb, or physical distance <=60 kb irrespective of LD. Comparisons are bidirectional, and all lead SNPs within a locus are evaluated.

Run:

```bash
Rscript 02_compare_subtype_loci.R \
  all_FUMA_locus_definitions.tsv \
  all_FUMA_locus_GWS_SNPs.tsv \
  ld_manifest.tsv \
  output/cross_subtype_loci
```

The principal downstream file is `06_main_subtype_pairwise_edges.tsv`, which can be supplied to analysis 3 for unified-region summaries.

## 3. Shared-control-adjusted effect comparison

Script: `03_compare_effects_shared_controls.R`

The combined FUMA locus table used here must include:

```text
phe  genomic_locus  locus_id  chr  locus_start  locus_end
top_snp  top_pos  top_p  n_lead_snps  lead_snps
```

The script expands all lead SNPs from the primary IDH, ISH, and SDH loci. It does not reduce a locus containing multiple lead SNPs to a single representative SNP.

### 3.1 GWAS manifest

The GWAS manifest has four columns and exactly one row for each primary subtype:

```text
phenotype	path	n_case	n_control
IDH	/path/to/idh.lmm.txt	9153	21588
ISH	/path/to/ish.lmm.txt	64389	21588
SDH	/path/to/sdh.lmm.txt	55396	21588
```

Each GWAS summary-statistics file must contain:

```text
SNP  chr  pos  A1  A2  beta  se  OR  eaf  pval  maf
```

The effect estimate `beta` is on the log-odds scale. Relative GWAS paths are interpreted relative to the manifest file.

### 3.2 Sample-overlap manifest

The sample-overlap manifest contains the three pairwise comparisons:

```text
phenotype_1	phenotype_2	n_overlap_cases	n_overlap_controls
IDH	ISH	0	21588
IDH	SDH	0	21588
ISH	SDH	0	21588
```

The script aligns effect alleles across the three GWASs, estimates the sampling correlation induced by the shared controls using the Lin-Sullivan framework, and compares effect estimates using a covariance-adjusted Delta/Wald statistic. Bonferroni correction is applied across all unique lead-SNP-by-subtype-pair tests.

The fourth argument is the locus-edge table generated by analysis 2. Use `NONE` if unified-region summaries are not required.

Run:

```bash
Rscript 03_compare_effects_shared_controls.R \
  all_FUMA_locus_definitions.tsv \
  gwas_manifest.tsv \
  sample_overlap.tsv \
  output/cross_subtype_loci/06_main_subtype_pairwise_edges.tsv \
  output/shared_control_effects
```

Methodological reference: Lin DY, Sullivan PF. *American Journal of Human Genetics*. 2009;85:862–872. PMID: 20004761.

## 4. Effective-sample-size standardization

Script: `04_standardize_effective_sample_size.R`

For each case-control GWAS, effective sample size is calculated as:

```text
N_eff = 4 / (1 / N_case + 1 / N_control)
```

The target is the smallest effective sample size across the three primary GWASs. Effect estimates are unchanged; standard errors are multiplied by `sqrt(N_eff_original / N_eff_target)`, and P values are recalculated. Locus retention is evaluated only among lead SNPs prespecified by the original FUMA analysis; no replacement SNP is selected after standardization.

The first two inputs are generated directly by analysis 3:

```text
04_harmonized_effects.tsv
01_lead_SNP_source_manifest.tsv
```

The sample-size table contains:

```text
phenotype	n_case	n_control
IDH	9153	21588
ISH	64389	21588
SDH	55396	21588
```

Run:

```bash
Rscript 04_standardize_effective_sample_size.R \
  output/shared_control_effects/04_harmonized_effects.tsv \
  output/shared_control_effects/01_lead_SNP_source_manifest.tsv \
  sample_sizes.tsv \
  output/effective_sample_size
```

Methodological reference for the case-control effective sample size: Willer CJ, Li Y, Abecasis GR. *Bioinformatics*. 2010;26:2190–2191. PMID: 20616382.

## Scope and data availability

The original working scripts also contained local data-management steps, one-off file conversions, and analyses comparing study loci with previously published loci. Those operations are not part of the four analyses above and are not included here. In particular, novelty classification is methodologically separate from cross-subtype locus overlap.

Participant-level UK Biobank data cannot be redistributed. The released scripts, required input schemas, analysis thresholds, and command-line interfaces are provided so that authorized researchers can apply the same procedures to appropriately prepared inputs. GWAS summary statistics made available with the article should be used in accordance with the accompanying data-access statement.
